# Датасет для оценки моделей (P4)

## Что здесь лежит

| Файл | Что |
|---|---|
| `README.md` | этот файл |
| `prompts.json` | снапшот промптов на момент сбора датасета (для воспроизводимости) |
| `export_raw.py` | скрипт выгрузки вакансий из БД в raw-файл |
| `raw_YYYYMMDD.txt` | вакансии с описаниями, оценками агента и сырыми ответами LLM |
| `reference_YYYYMMDD.txt` | эталонная разметка (пока не создан — нужен для сравнения) |

## Формат raw-файла

Каждая вакансия — отдельный блок, разделённый маркерами:

    @@@VACANCY_BEGIN@@@ <vacancy_id>
    TITLE: ...
    COMPANY: ...
    URL: ...
    STATUS: ...
    SALARY: ...
    DISCOVERED_AT: ...

    PROMPT_VERSION: <12 hex>
    MODEL: <имя модели>
    PROVIDER: <провайдер>
    LATENCY_MS: ...
    TOKENS_IN: ...
    TOKENS_OUT: ...

    --- AGENT_VERDICT ---
    llm_decision: reject / approve / n/a
    llm_reason: ...
    confidence: ...
    fit_summary: ...

    --- AGENT_EVALUATION_JSON ---
    {"suitable": ..., "requirements": [...], "verdict": "..."}

    --- DESCRIPTION ---
    <полный текст вакансии>

    --- LLM_RAW_RESPONSE ---
    <сырой ответ модели до парсинга>

    @@@VACANCY_END@@@ <vacancy_id>

## Ключевые правила

**Маркеры уникальны.** `@@@VACANCY_BEGIN@@@` с тремя собачками —
в текстах hh.ru такого не бывает. Если внутри вакансии встретится
`---` или `===`, это безопасно.

**vacancy_id дублируется** в BEGIN и END. Если блок побит — сразу видно,
какой именно.

**Один блок = одна вакансия.** Копируешь блок между маркерами целиком —
можно вставлять в чат DeepSeek, в другое окно, в любой мессенджер.

## Команды

**Выгрузить все новые вакансии из БД:**

    cd ~/hh-ai-agent
    python3 docs/datasets/export_raw.py

Скрипт идемпотентен: уже выгруженные вакансии повторно не пишутся.
Имя файла — `raw_YYYYMMDD.txt`, за сегодня один файл, дописывается.

**Сколько вакансий в файле:**

    grep -c "@@@VACANCY_BEGIN@@@" docs/datasets/raw_*.txt

**Список id в файле:**

    grep "@@@VACANCY_BEGIN@@@" docs/datasets/raw_*.txt

**Извлечь одну вакансию:**

    awk '/@@@VACANCY_BEGIN@@@ 12345/,/@@@VACANCY_END@@@ 12345/' docs/datasets/raw_*.txt

**Удалить одну вакансию (если что-то не так):**

    awk '!/@@@VACANCY_BEGIN@@@ 12345/,/@@@VACANCY_END@@@ 12345/' \
      docs/datasets/raw_*.txt > /tmp/clean.txt && mv /tmp/clean.txt docs/datasets/raw_*.txt

(внимание: awk с двумя диапазонами — проверить на маленьком примере)

## Рабочий процесс P4

1. **Сбор данных.** Агент работает, обрабатывает вакансии, данные пишутся
   в `agent.db` (`description`, `evaluation_json`, `raw_response`).
   Периодически запускаем `export_raw.py` — накопленное уходит в `raw_*.txt`.

2. **Ручная разметка в DeepSeek.** Открываем чат DeepSeek (или другую
   сильную модель). Кидаем один блок за раз. Просим:
   - пройтись по требованиям вакансии
   - оценить соответствие кандидату из `prompts.json` (или отдельным блоком)
   - дать свой вердикт: подходит / не подходит / спорно
   - привести требования по уровням
   Ответ DeepSeek сохраняем в `reference_YYYYMMDD.txt` симметричным форматом.

3. **Парсинг reference.** Скрипт парсит ответы DeepSeek →
   структурированный reference.

4. **Сравнение.** Скрипт считает:
   - Precision / Recall / F1 по вердикту (suitable / not suitable)
   - Совпадение по каждому требованию (match ±0.2)
   - Типы ошибок: ложный отказ, ложное срабатывание, потерянное требование,
     выдуманное требование, неверный match, неверный verdict

5. **Отчёт.** `report_YYYYMMDD.md` — где какая модель ошибается,
   какая лучше для какого шага.

## Что НЕ пишем в датасет

- `system_instructions` и `user_content` — политика проекта (не храним в БД).
  Промпт берём из `prompts.json` (снапшот на момент сбора).
- Персональные данные кандидата — они есть в user_content, но мы их не пишем.

## Версионирование

`prompt_version` в блоке — это `sha256(system_instructions)[:12]`.
Если правила 1-24 в `ai_analyzer.py` менялись — pv менялся.
Для чистоты сравнения в одном датасете держим один pv. Если pv
разные — фильтруем.

## Связь с коммитами

- `prompts.json` соответствует коммиту, в котором был собран.
- При обновлении промпта — обновляем `prompts.json` (скрипт
  извлечения — в истории коммитов, можно повторить).
